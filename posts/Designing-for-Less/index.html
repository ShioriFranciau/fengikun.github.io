Designing for Less

2026.10.12 约 536 字 2 分钟阅读

A quiet reflection on what happens when we remove the unnecessary.

A quiet reflection on what happens when we remove the unnecessary. Every interface is an argument about what matters, and the best ones argue quietly.

The problem with complexity

There is a tendency to believe that better design requires more features. More options. More interactions. More things competing for attention.

But sometimes, the best improvement is simply knowing what to remove.

When everything is important, nothing is. A complex system creates cognitive load, and a distracted mind cannot do deep work[1]. The cost is rarely visible on a feature list — it shows up as hesitation, as fatigue, as the quiet decision to close the tab and come back never.

The solution isn't always to add more — it's to remove what doesn't serve the core purpose.

Where the load comes from

Complexity rarely arrives all at once. It accumulates through small, defensible decisions: one more settings panel, one more badge, one more way to share. Each addition is reasonable. Together they become noise.

Three signals usually indicate that a product has crossed the line:

  • Users complete the task, but describe it as exhausting.
  • The onboarding takes longer than the task itself.
  • Features exist that the team cannot explain in one sentence.

Making room for content

The fix is not decoration — it is space. Whitespace is not empty; it is the material that gives content its shape. A page with a single column, a comfortable measure of about 70 characters per line, and a generous line height invites you to stay. A page crowded with widgets invites you to leave.

Practical rules that survive contact with real projects:

  1. One primary action per view. Everything else can be quieter.
  2. Restrict color to meaning. If everything is blue, nothing is.
  3. Let typography do the hierarchy work before reaching for borders and shadows.
  4. Treat motion as feedback, never as entertainment.

Learning to leave things out

The hardest discipline is refusing good ideas. A feature can be well-built, well-requested, and still wrong for the product. The test I return to is simple: does this help someone read, understand, or decide? If not, it is decoration — and decoration compounds[2].

Added element Reads as Usually worth it
Progress bar Orientation Yes
Auto-playing carousel Noise No
Search Escape hatch Yes
Social widget row Clutter Rarely

Removing things is uncomfortable because every removal deletes someone's favorite detail. But a design that tries to respect everyone ends up respecting no one's attention. Subtraction is not the absence of care — it is care, applied with an editor's hand.

Less noise. More reading.

Herbert Simon observed that a wealth of information creates a poverty of attention. ↩

Edward Tufte calls it "chartjunk" when it appears in graphics; the same logic applies to interfaces. ↩
